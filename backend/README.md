# Look — backend

FastAPI + SQLAlchemy 2 + Pydantic v2. Вход по одноразовому коду, профиль и местоположение, погода,
каталог, автоподбор образов, гардероб, лента, избранное, учёт кликов по реферальным ссылкам.

## Запуск

```bash
cd backend
uv sync
cp .env.example .env            # для разработки включите DEV_RETURN_CODE=true
uv run uvicorn app.main:app --reload --host 0.0.0.0 --port 8000
```

- Swagger: http://localhost:8000/docs
- С телефона (Expo Go) — по IP компьютера: `http://<IP>:8000` (приложение определяет адрес само)
- Настройки — переменные окружения или `.env` (см. `.env.example`). По умолчанию SQLite-файл `look.db`,
  фото в `./media`. Для Postgres: `DATABASE_URL=postgresql+psycopg://...` (и `uv add "psycopg[binary]"`).
- Таблицы создаются при старте, миграций (Alembic) пока нет: после изменения схемы dev-базу `look.db` удалите.

## Тесты и линт

```bash
uv run ruff check . && uv run pytest          # 700+ тестов, покрытие 100%
uv run pytest --cov=app --cov-report=term-missing
```

## Архитектура

Зависимости направлены внутрь: `api` → `application` → `domain`, а `infrastructure` реализует порты `application`.

| Слой | Что внутри |
|---|---|
| `app/domain/` | сущности, правила профиля, движок автообразов, погода, регионы — чистые функции |
| `app/application/` | **use cases** (по классу на операцию), порты (`ports.py`: репозитории, `UnitOfWork`, внешние сервисы), политики, ошибки |
| `app/infrastructure/` | SQLAlchemy-**репозитории** и `UnitOfWork`, Open-Meteo, файловое хранилище, часы, хэши |
| `app/api/` | тонкие роутеры, схемы, презентер (домен → JSON), перевод ошибок в HTTP, сборка зависимостей (`container.py`) |

Новая функциональность = use case + (при необходимости) метод репозитория + роутер.

## Тесты

Каждый тест разбит на секции `# Arrange` / `# Act` / `# Assert` (для `pytest.raises` — `# Act / Assert`).

- `tests/domain` — чистая логика, без подделок;
- `tests/application` — use cases на подделках из `tests/fakes.py` (репозитории в памяти с настоящей транзакционностью);
- `tests/infrastructure` — **контрактные тесты репозиториев** гоняются и на подделке, и на SQLite (если подделка
  разойдётся с настоящей реализацией, упадёт один из прогонов); адаптеры Open-Meteo — на подставном HTTP;
- `tests/api` — сквозные, через `TestClient`, со всеми внешними сервисами и временем подставными.

## Как работают ключевые вещи

- **Вход**: `POST /auth/code` (телефон или почта) → `POST /auth/verify` (код) → токен сессии. Код хранится в виде
  HMAC-хэша, живёт 5 минут, 5 попыток, пауза 60 секунд между отправками, не больше 5 кодов в час.
  Токен хранится в базе только как хэш; `POST /auth/logout` отзывает его.
- **Отправка кода**: порт `CodeSender`. Сейчас `ConsoleSender` (пишет в лог) — **только для разработки**:
  с `ENV=production` приложение откажется стартовать с ним, с дефолтным `SECRET_KEY` и с `DEV_RETURN_CODE`.
  SMS/почтового провайдера пока нет — подключается реализацией порта.
- **Профиль**: `GET/PATCH /me` (имя, год рождения, для кого, стили, бюджет, местоположение).
  Координаты хранятся огрублёнными до ~1 км. `GET /geo/cities?q=` — поиск города, `GET /weather` — погода
  в городе пользователя (Open-Meteo, кэш 15 минут).
- **Подбор образов** учитывает погоду (тепло образа, дождь), бюджет, стили (или стиль региона, пока человек
  «не определился») и «для кого». Таблица региональных стилей (`domain/regions.py`) — эвристика-заглушка.
- **Реферальная ссылка** не отдаётся в каталоге: «Купить» вызывает `POST /products/{id}/click`, сервер пишет клик
  и возвращает ссылку. Сюда добавятся ERID и параметры партнёрской сети.
- **id образа** хранит id его вещей (`c.<товар>~w.<вещь гардероба>`) — образ восстанавливается из id.
